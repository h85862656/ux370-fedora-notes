三、第一階段：Windows 準備

為什麼要做

Windows 的修復環境（進階啟動、重設這台電腦等功能）放在 p4。Windows 是用「從硬碟開頭算起的位置」記住 p4 在哪裡（設定檔裡記錄的位置是 321233354752 位元組，正好是 p4 目前的起點）。這次 p4 要往後移，這個數字就會對不上。先把修復環境暫時關閉，Windows 會把它收回 C 槽保管；分割做完再重新開啟，Windows 就會把它放回 p4 的新位置。

步驟

  1. 開機時出現 GRUB 選單（黑底、上面寫「GRUB version 2.12」、有好幾行可以選），用方向鍵 ↓ 選到「Windows Boot Manager (on /dev/nvme0n1p2)」，按 Enter
  2. 按開始，搜尋 cmd，在「命令提示字元」上按右鍵 →「以系統管理員身分執行」
  3. 先查看目前狀態，輸入： 
    reagentc /info
    預期看到：
    「Windows RE 狀態：Enabled」
    「Windows RE 位置：\\?\GLOBALROOT\device\harddisk0\partition4\Recovery\WindowsRE」
    用手機拍下這個畫面。
  4. 暫時關閉修復環境，輸入： 
    reagentc /disable
    預期看到「REAGENTC.EXE: 作業成功」
  5. 再查一次，輸入： 
    reagentc /info
    預期「Windows RE 狀態」變成 Disabled，位置變成空白。拍照。
  6. 用「關機」關閉 Windows。不要用「休眠」或「睡眠」。（休眠的話 GParted 會拒絕調整 Windows 分割區）

如果 reagentc /disable 失敗：拍照，不要繼續，關機回 Fedora 找 Claude。

四、第二階段：開機進入 GParted Live

  1. 確認筆電已關機、充電器已插上，插入 GParted Live 隨身碟
  2. 按電源鍵，看到 ASUS 標誌時連續按 ESC，叫出開機選單
  3. 選擇隨身碟（通常是「UEFI:」開頭加隨身碟品牌名稱），按 Enter
  4. 出現 GParted Live 選單，選第一項「GParted Live (Default settings)」，按 Enter
  5. 出現「Configuring console-data」鍵盤設定畫面：直接按 Enter（使用預設的「Don't touch keymap」）
  6. 出現「Which language do you prefer」語言選擇：直接按 Enter（預設英文，手冊裡的按鈕名稱都以英文為準）
  7. 出現「Which mode do you prefer」：直接按 Enter（預設 0，啟動圖形介面）
  8. 出現桌面，GParted 會自動開啟

開不起來的情況

  • 開機選單裡沒有隨身碟：重新插拔隨身碟、換一個 USB 孔再試
  • 出現其他錯誤畫面：這台的 Secure Boot 是關閉的，不會有 Secure Boot 問題。出現任何錯誤就拍照，關機回 Fedora 找 Claude，不要自己進 BIOS 改設定

五、第三階段：確認畫面

  1. GParted 視窗右上角有磁碟選單，確認選的是 /dev/nvme0n1 (931.51 GiB)。
    選單裡應該只有兩顆：/dev/nvme0n1（931.51 GiB）和隨身碟（通常是 /dev/sda，容量是你隨身碟的大小）。絕對不要對隨身碟做任何操作。
  2. 對照下表，確認分割區清單一模一樣（數字可能有小數點後一位的差異）：
    PartitionFile SystemLabelSize
    /dev/nvme0n1p1unknown128.00 MiB
    /dev/nvme0n1p2fat32SYSTEM260.00 MiB
    /dev/nvme0n1p3ntfsOS298.79 GiB
    /dev/nvme0n1p4ntfs1.31 GiB
    /dev/nvme0n1p5ntfs600.20 GiB
    /dev/nvme0n1p6ntfsRECOVERY822.80 MiB
    /dev/nvme0n1p7ext42.00 GiB
    /dev/nvme0n1p8btrfsfedora28.03 GiB
    另外可能看到一兩行很小的「unallocated」（未配置空間，幾 MiB 以下），那是正常的。
  3. 確認沒有任何分割區名稱旁邊有鑰匙（鎖頭）圖示。有鑰匙代表正在使用中，無法調整。
  4. p1 旁邊可能有黃色驚嘆號，那是因為微軟保留區沒有檔案系統，正常。

清單跟上表對不起來（多一個、少一個、大小差很多）→ 停手，拍照，關機回 Fedora 找 Claude。

六、第四階段：分割操作（共 8 步）

通用操作說明（每一步都會用到）

  • 選分割區：在清單中用滑鼠左鍵點一下那一行
  • 調整大小／移動：在那一行按右鍵 →「Resize/Move」。會跳出對話框，裡面有三個數字欄位：
    欄位（英文）意思
    Free space preceding (MiB)這個分割區前面要留多少空白
    New size (MiB)這個分割區的新大小
    Free space following (MiB)這個分割區後面要留多少空白
    在欄位裡輸入數字後，一定要按一下 Tab 鍵，其他欄位才會自動更新。
    下方「Align to」維持「MiB」不要改。這個選項會讓每個分割區的起點都落在 1 MiB 的整數倍上，也就是 SSD 的「4K 對齊」。改掉的話，分割區可能沒對齊，SSD 每次讀寫都要多碰一個內部區塊，速度變慢、磨損變多。
    數字差 1 是正常的：GParted 會自動把位置調到 1 MiB 的整數倍，所以各步驟看到的數字可能跟手冊差 1（例如 613378 變成 613379），這不影響結果，也不會破壞對齊。差 2 以上才算「對不上」。
  • 套用：每做完一步，按上方工具列的綠色勾勾（Apply All Operations）。會跳出確認視窗，警告編輯分割區可能造成資料遺失，按「Apply」。進度視窗跑完會顯示「All operations successfully completed」，按「Close」。
  • 移動分割區時的警告：移動 p4、p7、p8 時，GParted 會跳出「Moving a partition might cause your operating system to fail to boot」（移動分割區可能導致作業系統無法開機）。這是預期中的警告，按「OK」。後面的階段會處理開機問題。
  • 套用中途：不要關機、不要闔上螢幕、不要拔隨身碟、不要拔充電器。螢幕變黑的話動一下滑鼠即可。

步驟 1：刪除舊資料槽（p5）

目的：空出 600 GB，後面的步驟才有空間移動分割區。

  1. 點選 /dev/nvme0n1p5（ntfs，600.20 GiB）。再三確認大小是 600.20 GiB。
  2. 按右鍵 →「Delete」
  3. 清單中 p5 那一行變成「unallocated」約 600.20 GiB
  4. 按綠色勾勾套用

預期時間：幾秒鐘

完成後確認：p4 和 p6 之間是一大塊約 600.20 GiB 的 unallocated。

步驟 2：刪除舊 RECOVERY（p6）

目的：這是早就沒在用的舊修復分割區，刪掉後它的位置之後會用來放 swap。

  1. 點選 /dev/nvme0n1p6（ntfs，標籤 RECOVERY，822.80 MiB）。確認標籤是 RECOVERY、大小是 822.80 MiB。不要點到 p4（1.31 GiB，沒有標籤）。
  2. 按右鍵 →「Delete」
  3. 按綠色勾勾套用

預期時間：幾秒鐘

完成後確認：p4 和 p7 之間是一大塊約 601.00 GiB 的 unallocated（剛才兩塊合在一起）。清單上已經沒有 p5、p6。

步驟 3：把 Windows 修復環境（p4）往後移並加大

目的：p4 緊貼在 Windows 後面，要先往後挪出 1.31 GiB，Windows 才有空間長大；同時把 p4 從 1.31 GiB 加大到 2.00 GiB，讓之後的 Windows 修復環境更新有足夠空間。

  1. 點選 /dev/nvme0n1p4（ntfs，1.31 GiB）
  2. 右鍵 →「Resize/Move」
  3. 對話框目前應該是：Free space preceding 約 0、New size 約 1337
  4. 把 Free space preceding 改成 1340，按 Tab
  5. 把 New size 改成 2048，按 Tab
  6. 確認三個欄位：Free space preceding 1340、New size 2048、Free space following 約 613378
  7. 按「Resize/Move」按鈕，出現移動警告按「OK」
  8. 按綠色勾勾套用

預期時間：1～2 分鐘（先搬再加大）

完成後確認：p3 和 p4 之間出現約 1.31 GiB 的 unallocated；p4 顯示 2.00 GiB。

步驟 4：讓 Windows（p3）長大

目的：Windows 從 298.79 GiB 變成 300.10 GiB。

  1. 點選 /dev/nvme0n1p3（ntfs，OS，298.79 GiB）
  2. 右鍵 →「Resize/Move」
  3. 把 New size 改成 307303，按 Tab
  4. 確認 Free space preceding 是 0（Windows 的起點絕對不能動）、Free space following 變成 0（或 1 以內）。
    New size 如果被 GParted 自動改成 307302，也是正常的，大小一樣會顯示 300.10 GiB。
  5. 按「Resize/Move」
  6. 按綠色勾勾套用

預期時間：1～3 分鐘（GParted 會先檢查 Windows 檔案系統再調整）

完成後確認：p3 顯示 300.10 GiB，p3 和 p4 之間沒有 unallocated 了。

可能的錯誤：如果出現「NTFS is inconsistent」或「hibernated」（休眠中），代表 Windows 沒有完整關機。停手，拍照，關機回 Fedora 找 Claude。

步驟 5：把 /boot（p7）往前移

目的：p7 往前挪，讓 Fedora 有空間往前長大。這一步同時決定了新資料槽和 swap 加起來的空間。

  1. 點選 /dev/nvme0n1p7（ext4，2.00 GiB）
  2. 右鍵 →「Resize/Move」
  3. 對話框目前 Free space preceding 應該約 613378
  4. 把 Free space preceding 改成 451250，按 Tab
  5. 確認 New size 仍然是 2048；Free space following 變成約 162128
  6. 按「Resize/Move」，出現移動警告按「OK」
  7. 按綠色勾勾套用

預期時間：1 分鐘以內

完成後確認：p4 和 p7 之間是約 440.67 GiB 的 unallocated（之後的資料槽＋swap）；p7 和 p8 之間是約 158.33 GiB 的 unallocated。

注意：從這一步開始動到 Fedora 的分割區。之後任何一步出錯都不要關機，讓畫面停著，用手機或另一台電腦找 Claude。

步驟 6：讓 Fedora（p8）往前長大 （最久、最關鍵的一步）

目的：Fedora 從 28.03 GiB 變成 186.36 GiB（Fedora「磁碟」程式會顯示 200.1 GB）。因為 Fedora 在硬碟最尾端，只能往前長，GParted 必須把整個 Fedora 的內容搬到新位置，約 28 GiB。

  1. 點選 /dev/nvme0n1p8（btrfs，fedora，28.03 GiB）
  2. 右鍵 →「Resize/Move」
  3. 把 Free space preceding 改成 0，按 Tab
  4. 確認 New size 變成約 190831（190830～190832 都可以）；Free space following 是 0
  5. 按「Resize/Move」，出現移動警告按「OK」
  6. 再確認一次充電器有插著。
  7. 按綠色勾勾套用

預期時間：5～15 分鐘。進度條可能停在同一個百分比很久，這是正常的。

這一步進行中斷電或關機，Fedora 一定會損壞。千萬不要拔充電器、不要闔上螢幕、不要按電源鍵。

看起來卡住時：點開進度視窗裡的「Details」，裡面會列出正在搬的資料量。數字有在變就是還在跑，繼續等。數字完全不動超過 1 小時，才用手機或另一台電腦找 Claude 討論下一步，不要自己強制關機。萬一真的要強制關機，之後就得用 Acronis 備份還原。

完成後確認：p8 顯示 186.36 GiB，p7 和 p8 之間沒有空白了。

步驟 7：建立新的資料槽

目的：在 p4 和 p7 之間的空間前段建立新的 NTFS 資料槽，Windows 會把它當成一般的資料磁碟。後段留給下一步的 swap。

  1. 點選 p4 和 p7 之間那一行「unallocated」（約 440.67 GiB）。確認大小約 440.67 GiB。
  2. 右鍵 →「New」
  3. 對話框設定：
    欄位設定
    Free space preceding0
    New size426674，按 Tab
    Free space following自動變成 24576（留給 swap），確認一下
    Create asPrimary Partition（預設）
    Partition name留空
    File systemntfs（從下拉選單選）
    LabelData（這是 Windows 裡顯示的磁碟名稱，想取別的名字也可以）
  4. 按「Add」
  5. 按綠色勾勾套用

預期時間：幾秒鐘

完成後確認：出現新的 ntfs 分割區 416.67 GiB，標籤 Data；它和 p7 之間剩下約 24.00 GiB 的 unallocated。

步驟 8：建立 swap 分割區

目的：給 Fedora 休眠用的空間。建好後 Fedora 不會馬上使用，之後設定休眠時才會用到。

  1. 點選新資料槽和 p7 之間那一行「unallocated」（約 24.00 GiB）。確認大小約 24.00 GiB。
  2. 右鍵 →「New」
  3. 對話框設定：
    欄位設定
    Free space preceding0
    New size維持預設的最大值（約 24576）
    Free space following0
    Create asPrimary Partition（預設）
    Partition name留空
    File systemlinux-swap（從下拉選單選）
    Labelswap
  4. 按「Add」
  5. 按綠色勾勾套用

預期時間：幾秒鐘

步驟 1～4：關機回 Fedora 找 Claude。
步驟 5～8：不要關機，用手機或另一台電腦找 Claude。
按錯了還沒套用上方「Edit」選單 →「Undo Last Operation」（還原上一個操作）或「Clear All Operations」（清除全部未套用的操作）。還沒按綠色勾勾之前，什麼都還沒真的發生。
做完後開機，沒出現 GRUB 選單，而是出現 grub rescue> 或黑底英文錯誤拍下畫面，不要在裡面輸入任何指令。用手機或另一台電腦找 Claude。這通常是 GRUB 找不到搬動後的 /boot，可以修復。
Fedora 開不了機拍下畫面，用 GParted Live 隨身碟或 Windows 開機，不要自己修。我們有三層備份：分割表快照（GitHub repo）、Acronis 整碟備份（460 GB 外接硬碟）、Fedora 設定備份（ACRONIS_MED 隨身碟）。

八、第五階段：回到 Fedora 確認

  1. GParted 做完後，按兩下桌面上的「Exit」圖示，選「Shutdown」關機
  2. 等完全關機後，拔掉 GParted Live 隨身碟
  3. 按電源鍵正常開機。應該會出現平常的 GRUB 選單，最上面一行就是 Fedora，直接按 Enter（或等 5 秒自動進入）
  4. 登入後打開 Claude Code（這個視窗），跟 Claude 說「分割做完了」，Claude 會檢查：
    • Fedora 是不是真的變成 200.1 GB
    • btrfs 檔案系統有沒有長大到填滿分割區（有時需要再補一個指令）
    • /boot、/boot/efi 有沒有正常掛載
    • p4 的分割區屬性（RequiredPartition）有沒有保留
    • swap 分割區是否建立正確（之後 04f 設定休眠會用到）
    • 建立新的分割表快照存進 repo（動工前那份記錄的是舊配置，之後若出問題要用新配置的快照才能還原）

第一次開機可能比平常慢一點，正常。

九、第六階段：回到 Windows 確認

  1. 重新開機，在 GRUB 選單用方向鍵 ↓ 選到「Windows Boot Manager (on /dev/nvme0n1p2)」，按 Enter。這一行指向 p2（EFI 分割區），這次沒有動它，所以應該照常能進 Windows
  2. 第一次開機 Windows 可能會自動檢查磁碟，讓它跑完，不要中斷
  3. 開「磁碟管理」（在開始按鈕上按右鍵 →「磁碟管理」），確認：
    • C 槽約 300.1 GB
    • 修復磁碟分割約 2.0 GB
    • 新的 Data 磁碟約 416.67 GB，有分配到磁碟機代號（通常是 D:）
    • 以前的 RECOVERY（0.8 GB）已經不在了，這是正常的
    拍照。
  4. 用系統管理員開命令提示字元（同第一階段），重新開啟修復環境： 
    reagentc /enable
    預期看到「REAGENTC.EXE: 作業成功」
  5. 確認狀態： 
    reagentc /info
    預期「Windows RE 狀態」是 Enabled，位置是 ...harddisk0\partition4\Recovery\WindowsRE。拍照。
    如果位置顯示的是 partition3，代表 Windows 把修復環境放在 C 槽，修復功能一樣能正常使用，拍照回報即可，不用緊張。
  6. 用「關機」或「重新啟動」回 Fedora，不要用休眠

如果 reagentc /enable 失敗：Windows 本身照常使用沒問題，只是修復功能暫時不能用。拍照回 Fedora 找 Claude。

十、做完要回報給 Claude 的東西

  1. 第一階段 reagentc /info 的兩張照片（關閉前、關閉後）
  2. GParted 最終畫面的照片
  3. Windows 磁碟管理的照片
  4. 第六階段 reagentc /info 的照片
  5. 過程中任何錯誤或跟手冊不一樣的地方
  6. 步驟 6（搬 Fedora）大約花了多久
